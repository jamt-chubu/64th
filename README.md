参加者がスマートフォンでプログラムと抄録を閲覧するためのWebアプリです。
2026年10月31日（土）〜11月1日（日） 長良川国際会議場。

GitHub Pages で公開しています。

## 構成

サーバー側の実行環境は不要です。PHP・データベース・Node.js は使用しておらず、
外部CDNや解析ツールも読み込んでいません。静的ファイルのみで動作します。

```
index.html          エントリーポイント（学会アプリ.html へ転送）
学会アプリ.html      アプリ本体。演題データと抄録本文を埋め込み済み
manifest.json       ホーム画面追加用
sw.js               オフライン動作用（Service Worker）
icon-192.png        アイコン
icon-512.png        アイコン
案内/               各企画の案内PDF 54ファイル
フロアマップ/        会場別の経路図 PNG 6ファイル
一般演題/更新pdf/    抄録PDF 153ファイル（0001.pdf〜0153.pdf）
.nojekyll           Jekyll によるビルドを無効化（必須）
.gitattributes      改行変換を無効化し、コミットしたバイト列のまま配信させる
```

## 公開手順

### 初回

1. リポジトリの **Settings → Pages** を開く
2. **Source** を `Deploy from a branch` にする
3. **Branch** を `main` / `/ (root)` にして Save
4. 数分待つと `https://<アカウント名>.github.io/<リポジトリ名>/` で公開される

`index.html` が `学会アプリ.html` へ転送するため、ディレクトリのURLでアクセスできます。

### 更新

ファイルを差し替えて push すれば自動で反映されます。

```bash
git add -A
git commit -m "案内PDFを差し替え"
git push
```

## 編集時の注意

### ファイル名の正規化（重要）

**macOS で追加したファイルは、必ず NFC に正規化してから commit してください。**

macOS はファイル名の濁点を分解した形（NFD）で保存しますが、git は NFC に変換して記録します。
`学会アプリ.html` 内の参照が NFD のままだと、Linux 上の GitHub Pages では
バイト列が一致せず 404 になります。実際に「ご挨拶」「シンポジウム」など
8ファイルでこの問題が発生しました。

確認用:

```bash
python3 - <<'EOF'
import os, unicodedata
for root, dirs, files in os.walk('.'):
    if '.git' in root: continue
    for n in files:
        if n != unicodedata.normalize('NFC', n):
            print('NFD:', os.path.join(root, n))
EOF
```

出力があれば、そのファイル名を NFC に直してから commit してください。

### アプリ本体のデータ

演題名・演者・時間・会場・抄録本文は `学会アプリ.html` に直接埋め込まれています。
これらを変更する場合は、元データ（確定スケジュールの xlsx、登録システムの演題一覧 xlsx、
抄録PDF）からの再生成が必要です。

### 差し替えるだけで反映されるもの

同じファイル名で上書きすれば、アプリ側の変更は不要です。

- `案内/` のPDF
- `フロアマップ/` のPNG
- `一般演題/更新pdf/` のPDF

### 参加者側の画面が更新されないとき

オフライン閲覧に対応しているため、端末に前回のデータが残る場合があります。
`sw.js` の `const VERSION = 'jamt64-v1';` を `'jamt64-v2';` のように変更して push すると、
参加者の端末で自動的に更新が適用されます。

## 個人情報について

アプリ本体には、演者・座長の氏名、所属機関名、演題情報のみを収録しています。
登録システムに含まれるメールアドレス・電話番号・住所は含まれていません。

抄録PDF本文には、著者自身が記載した連絡先が含まれるものがあります
（メールアドレス5件、電話番号87件）。これは抄録原稿の記載内容そのものであり、
抄録集PDFと同一の状態です。

登録システムから出力した xlsx には演者・座長の連絡先が含まれるため、
**このリポジトリには絶対に追加しないでください。**

## 来年度への引継ぎ

特定のサーバー機能に依存していないため、データを差し替えれば翌年も使えます。
必要なのは次の3点です。

1. 確定スケジュール（会場×時間の表形式）
2. 登録システムから出力した演題一覧 xlsx
3. 抄録PDF（演題番号4桁のファイル名）

加えて、各企画の案内PDFと会場のフロアマップがあれば、同じ構成で再生成できます。
